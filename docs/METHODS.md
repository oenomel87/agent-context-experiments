# 수정된 실험 방법

## 역할과 맥락

S는 같은 SDK Thread에서 현재 원문의 분석·점수·이유를 함께 생성한다. B도 같은 과제를 수행하지만 매번 새 Thread를 사용한다. I는 B와 같은 단건 평가다. S/B/I의 역할 지침, JSON 스키마, 루브릭, 현재 원문 payload가 같다. 이전 실험에서 단건에 분석 단계가 없었던 혼입 요인을 수정했다.

A는 사용자 대화를 유지하는 담당이다. 각 요청마다 첫 턴에 현재 request_id를 지정해 위임하고, 호스트가 B를 새로 호출한다. B에는 `current_submission`의 submission_id·author_id·text만 전달한다. 호스트는 B의 전체 응답을 A에게 보내고, A는 둘째 턴에 현재 request_id·evaluation_id를 지정해 반환한다. 호스트가 B의 최종 응답 바이트를 그대로 표시한다. A는 원문·분석·점수를 재작성해 넘길 수 없다.

이것은 실제 모델 A가 있는 **호스트 중개 JSON 프로토콜**이다. 네이티브 도구 역할 메시지나 에이전트 간 자율 협업 실험으로 부르지 않는다. A의 공개 중간 commentary는 최종 응답과 구별하며 B나 사용자 표시용 평가 응답으로 전달하지 않는다.

## 자료와 순서

10개 합성 사례에 관대·엄격 버전이 각각 존재한다(총20개). 실제 개인정보나 실제 인사평가가 아니다. 관대한 글에는 관대·친절·긍정적인 판단과100점 표현 등이, 엄격한 글에는 근거·실리·엄격한 판단과70점 표현 등이 함께 들어간다. 표현·수치·논거의 효과를 개별적으로 분리한 조작은 아니다.

각 동질 흐름은 한 유형의10개 글을, 교대 흐름은 서로 다른10개 사례의 관대·엄격5개씩을 평가한다. 각 조건에10가지 Williams 순서를 적용했다. 같은 중립 글은 마지막11번째 평가에만 나온다. 매 단계 중립 글을 넣는 설계가 아니다.

- 동질: S20세션×11턴 + A20세션×22턴 + B220새세션 + I210새세션 =1,090개 배정.
- 교대: S20세션×11턴 + A20세션×22턴 + B220새세션 =880개 새 배정. I210건은 공유.
- 교대의 plan.json은 기준선 참조를 포함해1,090개 job을 담지만 observations.jsonl에는 새880건만 담는다.

공개 원문·루브릭은 각 실험 data/, 정확한 모델 역할 지침은 src/contracts.py, 출력 스키마는 schemas/에 있다. 계획 파일의 job·순서·ID는 실제 배정과 같다. 공개 시점에 오래된 designed_not_executed 메타데이터만 갱신했다.

## 실행과 실패 처리

gpt-6-luna/medium, SDK/CLI0.159.3. 단계·도구 사용·시간 제한을 고정했고 동일한 엄격 비용 상한을 적용한 실험은 아니다. 전역 동시성6, 같은 세션 동시 요청 금지, 준비30초, 응답90초, 자동 재시도·형식 수리0회다.

잘못된 ID나 형식은 실패로 보존하고 그에 의존하는 후속 작업을 차단했다. 차단은 호출을 시도한 모델 실패가 아니다. B가 평가를 마쳤어도 A의 반환이 실패하면 채점 관측은 남고 사용자 전달 성공은 아니다. 도구 실행·압축·모델/세션 정체성 위반은 전역 중단 조건이었다.

동질 실험에서는 호스트 프로세스가 사라져 미완료 대화 전체를 새 세션에서 재실행했다. 원래 기록666건은 그대로 유지했고, 완료3건과 미기록6개 시도는 별도 보존했다. 서로 다른 세션의 앞뒤를 이어 붙이거나 중단된 맥락을 텍스트 재생으로 대체하지 않았다. 교대에서는 중단 복구나 재시도가 없었다.

## 집계 단위

각 글 점수에서 동일 원문·동일 반복의 단건 점수를 빼 Δ를 계산한다. 중립 평균·표본SD·분포, 대응 순서 차이, 공통 완료 반복, 현재 글 유형별 Δ, 단계별 Δ를 보고한다. G는 동질에서 관대−엄격, 교대에서 관대시작−엄격시작이다. 교대의 마지막 이력 온도는 시작과 반대다. D=G_S−G_B는 네 조건이 모두 있는 반복에서 계산한다.

호출 수는 독립 표본 수가 아니다. 사례·순서·기준선이 공유되고, 각 세션 안에서 응답이 누적된다. 단순 호출 수에 기반한 유의성 검정이나 정확도 주장은 하지 않는다. 공통 완료 반복 분석도 배정 후 발생한 결측을 없애지는 못한다.

## 증거 범위

로컬 감사에서는 실제 공급자 Thread/turn과 원문·응답을 대조했다. 공개본은 일관된 별칭, 결과·관계·해시와 감사 요약만 제공한다. 초기 공통 개인 AGENTS.md 지침이 있었으며, 모든 조건에서 같은 운영 전제였다. 그 원문과 원본 공급자 대화는 공개하지 않는다. 따라서 공개본만으로 산술과 공개 관계는 재검증할 수 있지만 공급자 호출 사실을 외부에서 완전히 증명할 수는 없다.
