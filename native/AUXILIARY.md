# 보조 실험: 실제 대화와 기록 재생 비교

주 실험의 네 조건과 별도 질문이다. 기본 배정 data/plan.json에는 들어 있지 않으며 자동으로 실행하지 않는다.

## 조건

- T: 실제 같은 세션에서 여러 글을 한 턴씩 평가한다. 분석 단계를 별도로 두지 않는1단계 평가다.
- R_match: 새 세션에 짝지은 T의 실제 과거 글·점수·이유를 넣어 현재 글을 평가한다. 현재 T 점수나 미래 응답은 제공하지 않는다.
- R_free: 기존 방식처럼 자기 과거 점수·이유를 매번 새 세션에 넣고 다음 글을 평가한다.

R_match는 과거 응답 내용을 맞춘 조건부 비교이고, R_free는 자기 판단 경로까지 달라질 수 있는 운영 비교다. 실제 user/assistant 대화와 JSON history의 표현이 달라지므로 T−R_match를 순수한 숨은 기억이나 세션 ID 효과라고 하지 않는다.

모든 조건의 공통 상위 지침과 루브릭은 동일하다. T 현재 턴에는 현재 글만 추가하고 SDK 대화를 중복해서 user payload에 넣지 않는다. R은 history를 현재 글 앞에 제공한다. 이력이 없는 첫 평가의 현재 글 요청은 단건과 같다.

## 중립 측정과 호출 수

이력0·1·5·10개에서 동일 중립 글을 측정한다. 실제 T 대화를 중간에 중립 글로 오염시키지 않도록 다음 세 개의 별도 대화를 쓴다.

- T@1: 글1→중립 글→종료,2호출.
- T@5: 글1…5→중립 글→종료,6호출.
- T@10: 글1…10→중립 글→종료,11호출.

입력2유형×10순서×19호출=380회다. 주된 현재 글 단계 곡선은T@10의10개 글만 사용한다. 별도 대화들의 실제 초기 응답은 서로 달라질 수 있으므로 동일한 내부 상태를 복제한 분기라고 주장하지 않는다.

R_match와R_free는 각각2유형×10순서×(현재 글10개+중립3개)=260회다. 분기 평가를 다음 글의 이력에 넣지 않는다.

| 실행 방식 | 호출 | 세션 | 의미 |
|---|---:|---:|---|
| 주 실험과 같은 배치의 공통 기준선 사용 | 900 추가 | 580 추가 | T380+R_match260+R_free260 |
| 보조 실험만 별도 시점에 독립 실행 | 1,110 | 790 | 위900+새 기준선210 |

주 실험1,090과 공통 기준선을 한 번만 공유하면 전체1,990회다. 두 실험을 분리된 시점에 각각 새 기준선으로 실행하면1,090+1,110=2,200회다. 공유는 같은 모델·설정·원문·반복에 연결된 기준선으로 명시적으로 묶을 때만 허용한다. 이전 실험 점수를 자동 재사용하지 않는다.

T의380회에는 중간 측정을 위한 재실행 비용이 포함돼 있다. 같은 10편과 마지막 중립 글을 평가하는 운영 부분은 T와 R_free 모두 220회다. 380회와 260회 전체를 그대로 단일/재생의 운영 비용 차이로 해석하지 않는다.

## 파일과 실행 경계

- data/auxiliary-plan.json:900개 보조 호출과 외부 공통 기준선 ID. 실제 기준선 기록의 출처·해시를 확인해 연결해야 한다.
- data/auxiliary-standalone-plan.json:새 기준선 포함1,110개 독립 배정.
- data/combined-plan.json:동일 배치에서 기준선을 공유하는1,990개 전체 배정. 주 실험을 요청했다고 이 파일을 기본 실행하지 않는다.

주 실험과 구분해 보고하고, 분석 단계를 추가한 S2/M2와 T의 차이를 단순한 세션 유지 효과라고 하지 않는다. native 세션의 실패·재개는 주 실험과 같은 엄격한 기록 규칙을 적용한다. 아직 실행하지 않았다.
