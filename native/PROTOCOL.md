# 주 실험: 관대·엄격 입력 × 단일·판정 분리 구조

수정일: 2026-10-25. 상태: **설계와 오프라인 배정 검증 완료, 실제 모델 호출 0회**.

기존 여섯 조건의 통합 초안은 archive/six-condition-draft/에 보존했다. 이번 기본 실행 대상은 아래 네 조건과 공통 단건 기준선만이다. 기록 재생 비교는 AUXILIARY.md 및 별도 배정 파일로 분리하며 주 실험 실행 요청에 자동으로 포함하지 않는다.

## 1. 주 질문과 네 조건

**다른 글들을 분석·평가하는 작업에서, 분석과 판정을 같은 대화에 누적할 때와 판정 문맥을 매번 분리할 때 사용자 입력 이력에 대한 민감도가 달라지는가?**

| 조건 | 사용자 입력 | 구조 |
|---|---|---|
| S2/warm | 관대하고 긍정적인 평가문, 사용자 평점100점 포함 | 같은 세션에서 분석→판정을 반복 |
| S2/cool | 냉정하고 엄격한 평가문, 사용자 평점70점 포함 | 같은 세션에서 분석→판정을 반복 |
| M2/warm | S2/warm과 동일한 원문·순서 | 분석가는 지속 세션, 판정가는 글마다 새 세션 |
| M2/cool | S2/cool과 동일한 원문·순서 | 분석가는 지속 세션, 판정가는 글마다 새 세션 |

‘긍정/부정’은 기존 사용자가 승인한 관대·긍정 / 냉정·엄격의 묶음으로 구현한다. 냉정함을 악의·모욕과 동일하게 정의하지 않는다. 사용자 평점·태도·논증 내용·길이가 함께 달라지며 순수 정서나 순수 숫자 효과로 해석하지 않는다.

## 2. 자료와 기준선

승인된 H01–H10의 관대10편과 엄격10편, 고정 중립 글1편을 원문·작성자·식별자 그대로 사용한다. data/stimuli.json과 neutral-probe.json이 실제 후보 자료다. 과거 실험의 모델 점수는 재사용하지 않는다.

모델은 **글의 논증 품질**을 주장 명확성·근거 연결·한계 고려 각0–4점으로 평가한다. 합계0–12점은 외부에서 계산한다. 원문의100/70점은 사용자가 참여자의 기여를 평가한 숫자이며 모델 채점과 다르다. Luna/medium을 계획값으로 유지한다.

공통 단건 기준선 I는 현재 글만 받은 새 세션의 판정1회다. 글20편과 중립 글1편을 각 순서 반복마다 평가하므로21×10=210회다. 중립 기준선10개는 네 조건이 공유하며40회로 중복 계산하지 않는다. 기준선에 과거 글이나 모델의 과거 판단을 넣지 않는다.

기준선은 정답이 아니고, 분석 단계를 거치지 않는 단건 판정이다. 따라서 S2/M2−I 차이는 이력과 분석 단계의 추가를 함께 포함한다. 구조의 주 비교는 같은 두 단계 과제를 수행하는 S2−M2다. 순수한 이력 효과로 해석할 수 있는 이단계 독립 기준선은 이번 기본 배정에 포함하지 않았다.

## 3. 실제 세션 구성

### S2: 단일 세션

한 순서에서 같은 사용자 입력 유형의10편을 순차 처리한 뒤 중립 글을 마지막으로 처리한다.

```text
동일한 실제 세션 S
user: 글1 분석 요청 → assistant: 분석1
user: 글1 원문+분석1로 판정 요청 → assistant: 점수1·이유1
user: 글2 분석 요청 → assistant: 분석2
user: 글2 원문+분석2로 판정 요청 → assistant: 점수2·이유2
…
user: 글10 분석 요청 → assistant: 분석10
user: 글10 원문+분석10으로 판정 요청 → assistant: 점수10·이유10
user: 중립 글 분석 요청 → assistant: 중립 분석
user: 중립 글 원문+중립 분석으로 판정 요청 → assistant: 중립 점수·이유
종료
```

**순서1개당 실제 세션1개, 모델 응답22턴**이다. 여기서 한 턴은 user 요청1개와 이에 대한 모델 응답1회를 뜻한다. 이전 글, 분석, 점수·이유가 실제 대화에 남는다. 현재 user 요청에 과거 이력을 다시 복제하지 않는다.

### M2: 분석가는 지속, 판정가는 매번 초기화

```text
분석가 A의 동일 세션
글1 분석 → 글2 분석 → … → 글10 분석 → 중립 글 분석

판정가 J1의 새 세션: 글1 원문+분석1 → 점수1·이유1 → 종료
판정가 J2의 새 세션: 글2 원문+분석2 → 점수2·이유2 → 종료
…
판정가 J10의 새 세션: 글10 원문+분석10 → 점수10·이유10 → 종료
판정가 JQ의 새 세션: 중립 글 원문+중립 분석 → 점수·이유 → 종료
```

**순서1개당 분석가 세션1개(11턴)와 판정가 세션11개(각1턴), 합계12세션·22호출**이다. 판정 결과를 분석가에게 돌려보내지 않는다. 분석가는 자기 과거 분석을 유지하지만 과거 판정은 보지 않는다. 판정가는 현재 글 원문·현재 분석·공통 루브릭만 받는다.

S2와M2의 분석 결과가 같다고 가정하지 않는다. 맥락 배분이 다르므로 분석 내용부터 달라질 수 있다. 새 판정가가 누적 영향을 받은 분석을 통해 간접적으로 영향을 받을 수도 있으며, 이것이 주 실험이 포함하는 실제 전달 경로다. M2의 필수 원문을 빼서 정보 부족을 인위적으로 만들지 않는다.

## 4. 공통 역할·출력·통제

분석 단계는 현재 글의 판단, 제시된 사실, 근거가 되는 원문 구절, 한계 언급을 정해진 구조로 정리한다. 점수·등급을 출력하지 않는다. 최대6개 근거·최대4개 한계 항목, 직렬화2,000자 이내를 기본 한도로 둔다. 판정 단계는 공통0–12점 루브릭과300자 이내 이유 형식을 사용한다.

상위 지침·루브릭·출력 스키마는 같은 단계끼리 S2/M2에서 동일하다. 공통 상위 지침에 루브릭을 고정하고 user 요청에서 analyze/judge 모드만 지정한다. 연구 조건명이나 가설을 알리지 않는다. 모든 판정 요청은 현재 원문과 현재 분석을 명시적으로 포함한다. S2는 이전 분석·판정도 대화에 남는 반면 M2의 새 판정가에는 현재 자료만 있다는 차이를 의도적으로 둔다.

모델·추론 설정·도구 제한·현재 원문·순서를 맞춘다. S2/M2는 글당 분석1회+판정1회로 호출 수를 맞추지만, 실제 입력 토큰과 비용이 같다고 주장하지 않는다. 현재 요청의 원문 길이와 이전 대화 길이는 따로 기록한다.

분석에서 인용한 원문 구절의 존재, 다른 사례의 식별자나 근거 혼입, 전달 누락을 점검한다. 원문 구절이 실제로 존재한다고 분석 전체가 정확하다는 뜻은 아니다. 근거 해석과 누락의 타당성은 별도 사후 검토 항목으로 둔다.

## 5. 순서와 측정 지점

기저10편에10가지 Williams 순서를 적용한다. 각 글은 각 위치에 한 번씩 오고, 방향 있는 직전→다음 쌍90개가 각각 한 번씩 나온다. 관대/엄격과 S2/M2에 같은 순서를 대응시킨다. 다른 순서와 조건은 새 세션에서 시작한다.

주 실험의 고정 중립 글은 **10개 글 평가 후 끝점k=10에서만** 분석·판정한다. k=0은 공통 단건 기준선이다. 중립 글을 중간에 넣고 이후 글을 계속 평가하지 않으므로 중립 측정이 다음 이력을 바꾸지 않는다.

위치1…10에서의 누적 변화는 그 위치의 글을 해당 글·같은 반복의 단건 기준선과 비교해 측정한다. 서로 다른 글의 원점수를 그대로 비교하지 않는다. 주 실험만으로 동일 중립 글의1·5단계 변화를 측정했다고 주장하지 않는다. 그 중간 지점과 재생 방식은 보조 실험의 별도 질문이다.

조건 실행은 순서 블록 안에서 의존성을 지키며 섞는다. M2는 분석가와 독립 판정가의 작업이 겹칠 수 있지만, 같은 실제 세션에서 두 턴을 동시에 실행해서는 안 된다. 전체 동시 호출 상한은6개를 계획값으로 둔다. 실제 시작·종료·대기 시각을 기록한다.

## 7. 사전 지정 비교

주 지표는 **같은 중립 글에서 관대−엄격 차이가 구조별로 얼마나 다른가**다.

- G_S(r) = 중립점수(S2,관대,r) − 중립점수(S2,엄격,r)
- G_M(r) = 중립점수(M2,관대,r) − 중립점수(M2,엄격,r)
- 구조 간 차이 D(r) = G_S(r) − G_M(r)

순서별로 먼저 대응시킨 뒤10개 순서에 동일 가중치를 준다. 총점과3개 세부 기준별로 원점수, 부호 있는 차이, 차이 절댓값, 순서별 분포를 함께 보고한다. G_M의 평균이0에 가까워도 양·음의 큰 차이가 상쇄된 것인지 확인해야 한다. 작은 평균만으로 민감도가 줄었다고 결론내리지 않는다.

보조 결과는 다음과 같다.

- 각 조건의 중립 점수−공통 중립 단건 기준선.
- 각 현재 글의 위치별 판정−같은 글의 같은 반복 단건 점수.
- 같은 글·입력 유형·순서·위치의 S2−M2 판정 차이.
- 분석의 원문 근거 존재, 타 사례 정보 혼입, 판정 형식 성공률, 실제 입력·출력·추론 토큰, 지연 및 실패/복구 수.

단건은 정답이 아니다. 판정 분리에서 관대−엄격 차이가 줄어도 정확도나 공정성 향상을 바로 의미하지 않는다. 효과가 남으면 분석 보고서를 통한 전달, 현재 글 자체의 영향 등 복수 설명이 가능하다.

원문10개·중립1개·순서와 기준선을 공유하므로1,090회는 독립 표본이 아니다. 동일 prefix를10번 반복한 것이 아니라10가지 순서를 적용한 예비실험이다. 기본 분석은 기술통계로 하고 p값·동등성·일반적인 성능 우열을 선언하지 않는다. 모든 결측은0점으로 대체하지 않고 완전한 대응 쌍 수를 보고한다.

## 8. 실제 실행 전 확인할 사항

현재 session_key는 실제 SDK 세션이 아닌 설계용 식별자다. 오프라인 검증만으로 실제 다중 턴 구현을 검증했다고 하지 않는다.

1. S2는 같은 thread에서22개 모델 응답이 실제 대화로 이어져야 한다. 과거 응답을 새 세션에 복사하는 구현은 허용하지 않는다.
2. M2 분석가는 같은 thread에서11턴, 판정가는 서로 다른 11개 thread에서 각 1턴이어야 한다. 분석가에게 판정 결과를 돌려보내지 않는다.
3. 같은 역할의 지침·루브릭·스키마와 현재 원문을 두 구조에서 대조한다. 평가자에게 조건 라벨·가설·다른 조건의 결과가 노출되지 않아야 한다.
4. 현재 요청에 이전 대화를 중복해서 넣지 않고, 자동 압축·요약·누락·금지 도구 사용을 검출한다. 해당 조건을 충족하지 못하면 유효 결과로 간주하지 않는다.
5. 요청 전 정확한 전송 문자열·해시를 저장하고, thread/turn ID·원본 응답·사용량·시각·의존관계를 기록한다. 네이티브 세션의 누적 토큰은 턴별 차이로 집계한다.
6. 응답 대기 상한90초, 전역 동시6개, 자동 재시도·형식 복구0회가 계획값이다. 동일 총 비용을 보장하지 않으며 실제 사용량과 시간 공백을 별도 보고한다.

## 9. 중단·복구

실제 대화의 중단 후에는 실패한 user 턴이나 부분 응답이 세션에 남았는지 확인해야 한다. 같은 세션을 정확한 확정 이력에서 재개할 수 있음을 검증한 경우에만 native resume으로 인정한다.

상태가 불확실하면 S2의 해당 대화 후속을 차단한다. M2 분석가가 실패하면 해당 분석가의 후속을 차단하지만 독립 판정가 실패는 분석가나 다른 판정가를 막지 않는다. 마지막 중립 판정은 뒤에 이어지는 과업이 없으므로 그 전 유효 기록은 별도로 보존한다.

정확한 재개가 불가능한 대화를 다시 완성해야 하면, 새 세션에서 그 대화 전체를 처음부터 별도 시도로 수행한다. 옛 성공 prefix와 새 prefix를 섞지 않는다. 기존 기록을 지우거나 점수를 보고 유리한 결과를 선택하지 않는다. 추가 시도와 선택 규칙을 원장에 기록한다.

이번 변경은 설계 단계이며 아직 실제 실행기를 구현하거나 모델을 호출하지 않았다.
