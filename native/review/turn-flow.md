# 주 실험의 실제 세션 구성

모든 응답은 실행 시 실제로 생성한다. 아래에는 가상 점수·분석을 넣지 않았다. 한 턴은 user 요청과 그에 대한 모델 응답 한 번이다.

## 단일 — 같은 세션22턴

| 실제 턴 | user 요청 | assistant 응답 |
|---:|---|---|
| 1 | 글1을 분석하라 | 실제 분석1 |
| 2 | 글1 원문과 분석1로 판정하라 | 실제 점수1·이유1 |
| 3 | 글2를 분석하라 | 실제 분석2 |
| 4 | 글2 원문과 분석2로 판정하라 | 실제 점수2·이유2 |
| … | … | … |
| 19 | 글10을 분석하라 | 실제 분석10 |
| 20 | 글10 원문과 분석10으로 판정하라 | 실제 점수10·이유10 |
| 21 | 고정 중립 글을 분석하라 | 실제 중립 분석 |
| 22 | 중립 원문과 분석으로 판정하라 | 실제 중립 점수·이유 |

여기까지가 한 순서의 한 세션이다. 다음 순서는 새 세션에서 시작한다. 관대 조건과 엄격 조건도 같은 세션에 섞지 않는다.

## 멀티 — 분석가1세션11턴 + 판정가11세션각1턴

분석가는 같은 세션에서 글1…10과 중립 글을 순서대로 분석한다. 자기 분석 기록은 남지만 판정가의 점수·이유는 받지 않는다.

각 판정가는 새 세션으로 시작해 공통 루브릭과 현재 글 전체, 해당 글의 분석만 받는다. 판정가 J1의 결과를 J2에게 제공하지 않는다. 중립 판정가도 같은 방식의 새 세션이다.

따라서 한 순서의 모델 호출은 두 구조 모두 분석11회+판정11회=22회다. 세션 수는 단일1개, 멀티12개다.

## 공통 단건 기준선

각 글은 새 세션에서 분석 단계 없이 판정1회만 수행한다.10반복×21편=210회다. 단건과 두 단계 조건의 차이를 분석 추가와 분리된 순수 이력 효과로 해석하지 않는다.

실제 대화와 JSON 기록 재생의 비교는 [보조 실험](../AUXILIARY.md)에 별도로 정의했다.
